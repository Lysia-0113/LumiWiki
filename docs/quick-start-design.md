# 完整快速上手指南：目录规划、隔离章节与初始 QA

“快速上手”是名称与任务导向，不是篇幅限制。目标是在本次授权和角色范围内，完整解释必要准备、功能入口、关键字段及依赖、操作、结果查看和已确认的异常处理。完整性依赖目录及逐项覆盖检查，不用字数、步数或截图张数代替。

继续使用 Pi SDK 1.4.0：Pi 管理单个会话的模型、工具循环、压缩与取消；宿主管理跨会话的章节队列、依赖、持久化、来源校验和发布。业务 Agent 不提供目标源码、Shell、任意脚本、数据库或 HTTP 请求工具。

## 三类会话与一个宿主

| 角色             | 输入与职责                                                                       | 权限                                                                            |
| ---------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 全局探索规划会话 | Wiki 索引、用户目标、菜单与代表性页面；提交完整目录                              | 只读导航与观察、`guide_outline`，无业务填写、文档或标注工具                     |
| 独立章节会话     | 当前章节任务、必要系统概览、目录摘要、依赖的简短事实；探索、核验、写作并提交本章 | 本章场景、浏览器、截图、`image_annotate`、`document_write`；不能发布全书或写 QA |
| 初始 QA 会话     | 一章已保存文字及可信编号说明；提取有依据的问答草稿                               | 仅 `initial-qa` Skill 和 `qa_write`，没有浏览器、画框、源码或任意文件工具       |
| 宿主             | 按依赖启动章节，检查覆盖与证据，保存、恢复并组装导出                             | 确定性校验与文件写入，不重新用模型压缩全部章节                                  |

在线问答不加载上述生成 Skill，也不开放 `image_annotate` 或文档写入工具。工具能力在创建 Pi 会话时过滤，不靠提示词自觉遵守。

每章使用全新的 Pi 内存会话和独立的知识/图片引用账本；即使 Wiki 很小也只注入目录，按需读本章相关页。不会传入规划者或其他章节的完整对话，也不会因为另一章读过页面就获得引用资格。

第一版**串行独占测试浏览器**，不是并行操作共享页面。每个会话启动时清除旧控件 ref 和观察过的控件类型；当前会话必须重新观察。浏览器登录态和服务端数据仍是共享的，模型上下文隔离不等于数据库隔离。跨角色会话、数据种子和重置仍需要宿主适配器。

## 目录和场景契约分离

全局初探用 `guide_outline` 提交：

- `title`、`audience`、`overview`，可选统一术语 `glossary`。
- 每章稳定 `id`、`title`、业务 `goal`、`scope`、明确的 `questions`。
- 可选 `prerequisites`、真实观察的 `entryUrls`、有效 `wikiPageIds`、`dependsOn`。

目录不是菜单清单，也不是预先猜测表单字段的测试契约。结构保留安全上限 64 章，不再把全书限定为八个短模块；章节不足或过大应按业务任务合理拆分，不以凑数量为目标。

依赖必须存在、不能重复或成环。章节按依赖调度；上游未完成的下游会明确受阻。交接只含来源文档、简短摘要和必要事实，例如测试单号及已验证状态。下游必须复查真实状态，不直接相信旧交接或重放写操作。

章节探索发现遗漏时可用 `guide_outline_update` 记录原因，追加章节或修订待执行章节。不能改写执行中、受阻或已经完成章节的范围来降低验收条件。修订历史及目录版本持久化。

每章深入观察后才调用 `quick_start_plan`，只允许定义当前章节的单模块契约。契约含场景目标、准备、前置条件、检查点、结果及清理描述。场景契约锁定后不能降低标准。当前每模块最多 16 场景、每场景最多 24 检查点是执行安全边界，而非写作篇幅目标。

## 章节执行及证据

章节顺序：观察与受限导航、定义契约、prepare、begin、逐步操作和 checkpoint/截图、verify、结果截图/标注、提交完整章节。

- 默认 `profile=admin`：成功场景至少两个中间检查点，其他分支至少一个。简单只读任务显式使用 `general`。
- 定位支持精确角色/名称、文本、label、testId、CSS。未知字段类型优先用 label，不猜未观察的 radio/combobox 等角色。
- 表格用 `row_fields` 指定唯一键和列值核对同一对象，不默认操作第一行。虚拟列表和分页只表示已实际读取的范围。
- 负向或零数量检查必须有唯一且可见的父范围，避免未加载页面假通过。
- 每个检查点和结果组核验后先截图再继续。跨页结果用 `outcomeIds` 分组，各组归档自己的截图。
- 同站非 GET/HEAD/OPTIONS 请求会撤销当前场景结果证据。计数只表示浏览器观察的请求，不是数据库事务版本，POST 查询也会保守地撤销结果。
- 宿主决定检查是否通过，模型不能提交 `passed:true`。成功提示、工具未报错或一次点击均不能替代业务结果。
- 无权限、数据或验证入口时记录真实限制；全部无法核验的章节用 `guide_chapter_block`。不能把未知等同于系统没有功能。

每章拥有独立的工具预算（默认 200）和时限（默认 1800 秒），规划默认 100 次工具调用。未保存章节且预算允许时，Pi 收尾 hook 最多续跑两次；错误、取消或受阻不自动重试业务写入。超预算停止当前会话，不占用后续章节配额。

## 浏览器、视觉与共享登录

快速上手和用户问答共用每个项目的目标网页、浏览器页面与登录状态。管理员先连接并登录，后续问答继续使用同一会话；问答结束不关闭浏览器。切换管理台项目不清除登录；修改目标网址或登录信息、关闭浏览器或重启服务后需要重新连接。浏览器被其他任务占用时提示稍后重试，不抢占页面。

`LLM_VISION=true` 时，观察、导航到新页面、返回和主动截图会把遮挡密码及 `[data-private]` 区域的视口图片与页面文字一起发送给模型；普通填写、点击仍返回页面结构，可按需再次观察。观察图片不会刷新 ref，也不当作已核验的指南证据；指南截图仍需通过原有核验流程。模型不支持图片时保持关闭；独立公共模型可用 `PUBLIC_LLM_VISION` 覆盖主模型设置。QA 的模型输入可以包含图片，保存和展示的答案仍为纯文字；初始 QA 会话只接收文字，不传截图。

## 完整章节和图文

`document_write` 支持完整摘要、适用角色、前置条件、补充业务解释、任意合理数量的步骤、结果查看、故障处理和限制，不再规定三至六步、每步一两句或 280 字符。

每章提交 `coverage`，逐一对应目录中的 `questions`，不能漏项或添加假问题。已解释标 `covered`，无法核实标 `limited` 并给原因；受限问题和受阻场景自动进入用户可见限制。结构检查不能证明解释的语义充分，仍需人工复核。

步骤保留旧 `imageId`，新增 `images: [{imageId, caption?}]`，支持一步多图。图片必须来自本章核验账本，不允许跨章复用来冒充当前证据。

标注规则：

- 只标注本段解释的目标，不框整页所有控件。
- 原图保留；使用原图冻结的 ref 或精确像素 box。
- 拒绝相交、嵌套、重复及接触的目标，给出缩小目标或拆图的错误提示，不静默删除。
- 编号采用确定性外置布局及短引线，避开目标、其他编号和引线。没有安全空间就明确失败，不覆盖被解释的目标区域。
- `label` 是短标题，`description` 是不截断的编号解释。宿主从可信 artifact legend 自动生成 HTML/Markdown 图下注解，不相信正文自造的编号映射。
- 导出完整正文、预期结果及全部选定图例；可信图例文字同时保存在章节 JSON，供初始 QA 读取，不加载截图像素。

## 持久化、恢复与发布

`src/guide-workflow.ts` 管理 `runs/<taskId>.json`，包含目录版本、修订历史、章节状态、尝试次数、版本、租约和来源文档。

章节状态：`pending / running / generated / blocked / failed`。任务状态：`planning / running / completed / partial / failed / cancelled`。

- 每次业务操作前记录可能产生副作用的动作类型，不保存填入的密码或任意参数。工具完成后更新本章核验与写请求计数；中断后重试必须先检查实际状态。
- 章节提交工具校验任务租约、版本、覆盖、图片与引用。文档渲染完成后以 JSON 为提交标记，立即保存章节完成状态，不依赖模型最后一句结束回复。
- 过期或跨章节任务不能覆盖新结果。单个任务和浏览器都有独占约束。
- 失败只影响本章及依赖章节，不阻止独立章节继续生成；不会为了缺口重跑无关的已完成章节。
- 管理台“快速上手”显示章节任务、缺口及继续按钮。服务重启后可重新连接并登录浏览器，用 `taskId` 继续任务；不恢复旧模型对话或旧 ref。
- 续跑会补缺失或受限章节。重做生产章节会使依赖其交接事实的消费者失效并更新版本，无关章节保持不变。
- 宿主按目录拼接已保存正文和离线图片，生成 HTML/Markdown 及可点击目录，不再让汇总模型重写全文。
- 全部章节已保存且没有未解释的覆盖缺口才是 `complete:true`；真实业务限制本身不等于缺口。部分指南明确 `partial`，全受阻不伪装生成成功。
- 界面区分运行结束、部分产出、完整指南和初始 QA 状态，不统一显示“本轮已完成”。

`refresh-guide.mjs` 只按已保存内容重新渲染导出，不调用模型、不精简正文、不更改 QA。

生成完成不等于公开发布。管理端选择指南或独立文档，预览步骤和截图后显式确认审核并发布。发布会保存一份独立图文快照，包含全部步骤图片和编号图下注解；草稿后续修改不影响已发布版本，再次审核发布才更新用户版本，相同内容重复发布不会创建新版本。可以撤回发布，撤回后列表、正文和各版本图片均不再对用户提供。部分模块未完成时保留并展示限制说明；缺少步骤或截图缺失时不能发布。

用户端只展示已发布的指南，不提供内部核验记录、源码引用或运行日志。`project` 参数绑定项目，管理台切换项目不改变用户链接内容。公开只读接口为 `GET /api/v1/public/guides`、`GET /api/v1/public/guides/:id` 及版本图片；`/user?project=:projectId&guide=:id` 可直达指南。QA 在用户端保持纯文字。

## 初始 QA 独立技能

`skills/initial-qa/SKILL.md` 与快速上手独立加载。每个有文档且缺当前版本 QA 的章节，使用新 Pi 会话处理。每章至少一条有依据的问答、最多三条，不强行凑数，取消整本最多二十条的限制。

输入是当前章节的文字、可信图例和引用，不包含整个指南、截图像素、浏览器、审计历史或其他章节上下文。工具仅 `qa_write`，只能追加待审核草稿，不修改原条目。

指南先落盘，再运行初始 QA；QA 拥有自己的工具、输出和时间预算。失败保留指南及已有问答，单独重试只补缺章，不重新探索浏览器。按 `documentId` 关联版本；旧审核条目保留为历史，但章节更换后不用于当前用户直答。生成期间指南版本变化不能误报当前 QA 已完成。

## 在线问答与可用性

管理端 QA 和用户端回落 Agent 共用 `src/qa-prompt.ts`，都能读取当前项目 Wiki：小库全文注入，大库提供目录和 `wiki_read` 按页、小节读取。回答通过 `qa_finish` 提交 `outcome / scope / evidence`，宿主决定是否入库，模型不能直接写 QA。澄清、证据不足、个人或实时状态不推断为可复用。

所有可用问答参与召回，已核验答案优先；停用条目不参与。人工核验与启用/停用互不影响，停用候选标为已核验也不会自动启用。完整、自包含、引用为当前项目实际读取且版本仍有效的 Wiki 页的通用回答，保存为可用未核验 QA；本会话读取过浏览器内容时，即使模型省略网页引用，也只保存为停用候选。编辑问答内容会清除旧的自动入库证据，单独修改核验或启用状态保留证据。首次模型回答和未核验直答显示“尚未经人工核验”提示。

指南整理出的初始 QA 通过 `documentId` 关联章节版本；章节更换后旧草稿和审核条目保留为历史，但不再参与当前直答。

## 核心文件与验证

- `src/agent.ts`：会话工厂、阶段工具注册、逐章调度、取消和独占浏览器。
- `src/guide-workflow.ts`：目录、依赖、版本租约、持久化恢复及确定性组装。
- `src/guide-policy.ts`：宿主工具与规划动作白名单。
- `src/quick-start.ts`：章节内场景、声明式 UI 检查、证据和 Pi hooks。
- `src/artifacts.ts`、`src/documents.ts`：冻结标注、避让、多图和可信编号解释。
- `src/quick-start-qa.ts`、`src/artifact-agent.ts`：隔离初始 QA 会话与草稿门禁。
- `src/browser.ts`：项目共享浏览器、视觉截图与密码/私密区域遮挡。
- `src/publications.ts`：审核发布、版本快照、撤回和公开读取。
- `src/qa.ts`、`src/qa-admission.ts`、`src/qa-result.ts`、`src/qa-prompt.ts`：召回、核验/启用状态、结构化准入和统一提示词。
- `public/`：三栏工作台、章节任务面板和用户阅读页。
- `skills/quick-start/schemas/`：目录与场景契约 schema；示例和断言参考继续复用。

回归用本地模型协议桩真实运行 Pi SDK，并以真实 Chrome 核验浏览器和离线导出。覆盖上下文隔离、阶段权限、按章预算、跨章截图拒绝、部分指南恢复、依赖和版本、图文关联、初始 QA 隔离及幂等。真实付费模型验收脚本需显式运行，不把协议桩测试当作模型语义质量证明。

## 当前边界

检查等级仍为 `ui-checks`，契约和文档仍待人工复核。工具证明指定 UI 条件成立，不能证明全部业务规则正确、后端持久化和结算正确，或权限隔离已通过安全审计。目录及 coverage 由模型提出，宿主检查结构与证据，不宣称已有独立的全系统语义审稿器。

尚未实现：并行写业务的数据库隔离、通用自动种子/重置、SSO 适配、可信后端断言、任意角色自动切换、源码变更自动更新和公共反馈。不要通过放松证据门禁来弥补这些能力。
